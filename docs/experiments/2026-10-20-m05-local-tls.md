# M0.5 local TLS execution experiment

- Date: 2026-10-20.
- Scope: actual coordinator/agent/control execution on one developer machine.
- Result: local transport and evidence-collection demonstration passes; strict
  direct-launch qualification fails. M0.5 and portable-artifact acceptance remain
  open.

## Inputs and provenance

Base source commit: `1e1fb8b95d5442e5069f724463efc8010cc1d91f`, with uncommitted
M0.5 implementation changes. This is **not** an exact-commit certification.
[The sanitized evidence manifest](2026-10-20-m05-local-tls-evidence.json) records
each relevant source file's SHA-256, the lockfile, script, control, and agent
hashes. Dependency versions/checksums are pinned in `Cargo.lock`.

Build/execution host: macOS 26.5.2, build 25F84, Darwin 25.5.0, ARM64.
Rust: `1.93.0 (254b59607 2026-01-19)`, host `aarch64-apple-darwin`,
LLVM 21.1.8. This is a developer environment with Rust, Python, OpenSSL and other
tools installed; it is not a clean baseline. Physical/virtual status and actual
workload translation were not independently audited.

Commands:

```sh
just check
just lab-smoke
```

The script builds the agent with
`cargo build --locked --offline -p polystride-lab` and the native control with
`rustc --edition=2024 -C debuginfo=0 examples/lab-control.rs -o OUTPUT`.
`OUTPUT` is under the generated `artifacts/lab-smoke/run-*/` directory.
It provisions ephemeral certificates/tokens and executes queue, coordinator,
agent `--once`, and status commands. Both sides run on localhost using real TLS.

The first sandboxed smoke attempt could not bind the listener (`Operation not
permitted`); it supplied no execution evidence. The successful run was outside
that restriction. It did not install services or change host security settings.

## Results

| Control | Observation | Interpretation |
| --- | --- | --- |
| Native control | Unicode/literal args, expected stdout/stderr, exit 7; 247 ms | Recipe pass |
| Ten-second sleep, 80 ms deadline | Terminated; timeout true; 87 ms | Retained test failure; supervisor control passes |
| 128 zero bytes as executable | Exit 126, stderr says cannot execute binary file; 14 ms | Retained failure; **not** a direct spawn error |
| No-shebang shell sentinel | Printed `fallback-observed`, exited 23; 15 ms | Implicit shell fallback observed; strict direct-launch gate fails |
| Wrong TLS server name | Agent connection rejected before payload staging | Security control passes |
| Wrong host token | Job not delivered or staged | Security control passes |

All four payloads had matching before/after hashes and sizes. Timing is one local
sample, not a performance claim.

The shell sentinel's complete bytes are:

```sh
printf 'fallback-observed\n'
exit 23
```

There is no shebang. Its execution through `std::process::Command` shows that
this backend cannot stand in for a strict no-fallback native launcher on this
host. The malformed-input test initially assumed a spawn error and failed;
its preserved observation was exit 126. The tests now check the actual failure
without relabeling it as kernel rejection. The independent sentinel keeps the
launch-semantics defect visible.

`just check` passed formatting, Clippy with warnings denied, and 17 behavioral
tests. Those tests cover real native control behavior and include durable
duplicate delivery/report handling, interrupted receipts, credential scope,
artifact corruption/replacement, output overflow, environment/cwd/files, Unicode,
non-UTF-8 output, locks and protocol limits. These are local results only.

Raw local evidence is under `artifacts/lab-smoke/run-rf4ih_f9/`; private keys and
tokens also reside there and must not be committed or shared. The checked-in
manifest contains no credentials. Successful and failed reports are retained in
the coordinator's `results/` and the agent's per-job directories.

## Remaining acceptance

No Linux, Windows, or macOS x86-64 execution was performed. No universal artifact
was built. Workload-native CPU status, clean/offline/cache baselines, desktop
launch, signing/quarantine, and physical-machine distribution behavior remain
unverified. The current process supervisor only controls the direct child.

Next implement and qualify strict launch backends and process-tree supervision,
then deploy native controls to the first four hosts. Preserve this failed
fallback control when those backends are added.

## Pedantic lint follow-up

The initial `just check` run above enabled standard Clippy checks, not the
pedantic group. An explicit pedantic run found documentation, conversion,
ownership, function-length, and style findings. These were fixed without lint
suppression, and `clippy::pedantic` is now enabled in the workspace so the
existing `-D warnings` gate enforces it.

After the fixes, `just check` passed formatting, workspace/all-targets Clippy
including pedantic, and all 17 behavioral tests. `just lab-smoke` also passed
again, retaining the same failed controls and observed shell fallback.
